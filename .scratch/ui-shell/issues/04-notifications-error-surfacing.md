# 04: Notifications + error surfacing

**What to build:** non-modal notifications — toasts for connection lost, scope errors, and stack events arriving from the link, so the user is informed without modal dialogs. Demoable: mock scope drops the connection, a toast appears.

**Blocked by:** 01, 03

**Status:** implemented in 321685a

- [x] Link events/errors surface as toast notifications
- [x] No modal dialogs for background events
- [x] Toasts dismiss automatically and can be reviewed in a log
- [x] Tests: event → toast dispatch via mock facade

## Comments

Implemented keeping the strict pure/widget split (sandbox has no GTK — docs/wiki/assumptions.md; all link work is mock-only):

- **Pure layer** `ui/notifications.py` (stdlib only, NO `gi`, no top-level `link` import — event names re-declared as string constants): `NotificationSeverity(str, Enum)` `INFO`/`WARNING`/`ERROR`; frozen `Notification(severity, title, message, source, timestamp)` (severity coerced from str, naive datetimes read as UTC, empty title rejected). `NotificationBus(capacity=DEFAULT_LOG_CAPACITY=200)` — `add_listener`/`remove_listener` (idempotent, decorator-friendly), `push(notification)` appends to a lock-protected bounded `deque` ring buffer and notifies listeners synchronously on the pushing thread (returns `False` when a duplicate is dropped), `log()` newest-first, `clear()` (silent — no listener notification), `__len__`. **Dedup choice (documented):** consecutive identical `(severity, title, message, source)` notifications (timestamp ignored) are dropped, so a flapping link doesn't spam toasts; non-consecutive repeats (A, B, A) are kept. `NotificationController(bus, connection, *, invoke_on_main=None, subscribe=None)` — listens to `ConnectionController` snapshots: `ERROR` → ERROR "Connection error: <msg>", `RECONNECTING` → WARNING "Link lost — reconnecting…", `CONNECTED` after a reconnect → INFO "Reconnected" (the initial connect stays silent — the connection panel already shows it), `DISCONNECTED`/`ERROR` → unsubscribe device events. On `CONNECTED` it subscribes to the device's events through the injectable `subscribe(device, name, handler) -> unsubscribe()` callable (default `default_event_subscribe` uses the facade's `add_event_handler`/`remove_event_handler`) for `DEVICE_EVENTS = ("Stack", "scope_error", "stack_finished")`; device events are marshalled through `invoke_on_main` (worker-thread safe): Stack progress → INFO "Stacking…", `stack_finished` → INFO "Stack finished", `scope_error` → ERROR "Scope error: <detail>" (Stack state "idle" is skipped — covered by `stack_finished`). `detach()` unsubscribes everything (idempotent).
- **Widget layer** `ui/toast.py` + `ui/notification_log.py` (`gi` at module top, re-exported lazily from `ui/__init__` via PEP 562): `NotificationToasts(bus, overlay, *, invoke_on_main, on_open_log)` — bus listener marshals via `invoke_on_main` (the app binds `GLib.idle_add`, same pattern as `connection.py`) then `overlay.add_toast(Adw.Toast(title="<title>: <message>", timeout=TOAST_TIMEOUTS[severity]))` with severity-based auto-dismiss `INFO 5s / WARNING 7s / ERROR 10s` (errors stay longest; Adw default is 5s) and a "View" button opening the log; created toasts recorded in `.toasts` (test hook); overlay duck-typed so tests pass a fake. `NotificationLogDialog(Adw.Dialog)` — the reviewable log, opened ONLY by the user: one row per `bus.log()` entry (time · severity · source caption + title: message, `error`/`warning` css), newest first, with a **Clear** button (`bus.clear()` + refresh); hooks `bus`, `clear_button`, `rows()`, `row_count()`, `refresh()`, `row.notification`. No modal dialogs for background events — the bus is the only channel; the dialog is user-invoked only.
- **Wiring** `app.py`: `SeestarApplication` owns the shared `NotificationBus()` + `NotificationController(bus, connection_controller, invoke_on_main=_invoke_on_main)`; `SeestarWindow` wraps its whole content in an `Adw.ToastOverlay` (`toast_overlay`), creates the `NotificationToasts` presenter (`toast_presenter`), and adds a header-bar notifications button (`view-list-symbolic`) + `win.notifications` action → `_on_notifications_action` presents the `NotificationLogDialog` on the shared bus. Exposes `notification_bus`, `notification_controller`, `toast_overlay`, `toast_presenter`, `notifications_button`.
- **Exports:** pure names eager from `ui/__init__.py` (`NotificationSeverity`, `Notification`, `NotificationBus`, `NotificationController`, `NotificationListener`, `EventSubscribe`, `default_event_subscribe`, `DEFAULT_LOG_CAPACITY`, `CONNECTION_SOURCE`, `SCOPE_ERROR_EVENT`, `STACK_EVENT`, `STACK_FINISHED_EVENT`, `DEVICE_EVENTS`); widget names lazy (`NotificationToasts` → `toast`, `NotificationLogDialog` → `notification_log`).
- **Tests:** `tests/test_ui_notifications.py` (29 pure tests, headless): bus push/log/capacity ring-buffer eviction/clear/listener add-remove-decorator/dedup (consecutive identical dropped, A-B-A kept); `NotificationController` with a fake `device_factory`: connect failure → one ERROR with the message, lifecycle `connection_lost` → WARNING "Link lost", `reconnected` → INFO "Reconnected", initial connect silent, device events via the injectable subscribe (Stack progress → INFO, `scope_error` → ERROR, `stack_finished` → INFO, idle Stack skipped), disconnect/error unsubscribes device events, `invoke_on_main` marshalling, `detach()` idempotent; package exports; subprocess boundary test (pure ui imports no `gi`, no `link`). Integration with the REAL `Device` against `MockScope` on 127.0.0.1: connect (silent) → `drop_connections()` → WARNING reconnecting + INFO reconnected in the bus log → `mock_fail` request → ERROR "Scope error" → `start_stack`/`stop_stack` → INFO stacking/finished. `tests/test_ui_widgets.py` (`importorskip("gi")`, skips in this sandbox, runs on the desktop): window content wrapped in `Adw.ToastOverlay` sharing the app's bus + controller, notifications button + `win.notifications` action, `NotificationToasts` with a fake overlay (push → `add_toast` called, title/timeout per severity, "View" button, queued `invoke_on_main` not shown until drained, `detach()` stops), `NotificationLogDialog` lists the bus log newest-first with Clear emptying it, `_on_notifications_action` presents the dialog on the shared bus, lazy package exports.
