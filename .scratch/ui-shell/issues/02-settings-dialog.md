# 02: Settings dialog

**What to build:** a settings dialog for scope IP, PEM key path, and project root, persisted to a JSON file in the app config dir and reloaded on start. Demoable: change settings, restart app, values persist.

## Comments

Implemented on top of ticket 01's `ui/` package, keeping the strict pure/widget split (sandbox has no GTK — docs/wiki/assumptions.md):

- **Pure layer** `ui/settings.py` (stdlib only, NO `gi` import — subprocess-enforced): `validate_settings(values) -> dict field->error` (empty dict = valid = saveable) — `scope_ip` empty (unset) or a valid IPv4/hostname (reuses the now-public `state.validate_scope_ip`); `key_path` empty (unset) or a plausible path string, existence NOT required at validation time (the PEM key may not exist yet — a missing file is only flagged); `project_root` empty (unset) or an existing directory (missing dir = error). `flag_settings(values) -> dict field->flag` — soft warnings (key file not found, with an `extract-key` hint) that never block saving. `SettingsFieldError(SettingsValidationError)` carries `field` + `message` + the full `errors` dict. `SettingsController(state)` with `update(scope_ip=..., key_path=..., project_root=...)`: `None` kwarg = keep current, `""` = unset; the full candidate is validated first — on any hard error it raises `SettingsFieldError` and applies/persists/notifies NOTHING; on success it applies via `AppState.set_setting`, persists atomically via `AppState.save`, and notifies the observer list (`add_listener`/`remove_listener`, idempotent, decorator-friendly, listeners get a copy). `state.py` change: path settings now accept empty (unset, normalized to `""`) — `validate_path_setting`/`validate_scope_ip` made public for reuse.
- **Widget layer** `ui/settings_dialog.py` (`gi` at module top, re-exported lazily from `ui/__init__`): `SettingsDialog(Adw.Dialog)` — ToolbarView + HeaderBar (Cancel left, Save right `suggested-action`) + PreferencesPage/PreferencesGroup with one `Adw.EntryRow` per key, each with a validation label suffix (red `error` css class for hard errors, amber `warning` for flags). Live validation on every entry `changed`. **Save semantics (documented choice): the Save button is insensitive while any hard validation error exists** (chosen over blocking the click, so the user sees immediately why saving is impossible); soft flags never block; `save()` returns whether it persisted. The dialog registers itself as a controller listener, so external changes refresh the entries while open. `app.py`: `SeestarApplication` owns the shared `SettingsController` (startup load already via `load_state`; the scope IP it holds is what ticket 03's connect will use); the header bar gained a menu button whose **Settings** item activates the window-level `win.settings` action, which presents the dialog; the window observes the controller (scope IP shown in the menu-button tooltip).
- **Exports:** pure names eager from `ui/__init__.py` (`SettingsController`, `SettingsFieldError`, `SettingsListener`, `validate_settings`, `flag_settings`); `SettingsDialog` lazy (PEP 562).
- **Tests:** `tests/test_ui_settings.py` (45 pure tests, tmp_path only): per-field `validate_settings` errors (bad IP, non-str/NUL path, missing project_root dir, unknown key, only-present-keys checked, multiple at once), `flag_settings` (missing key file flagged with hint; existing/unset not), `SettingsFieldError` attributes, controller `update` valid -> persisted + reloaded on a fresh `AppState`, partial update keeps other fields, unset (`""`) round-trip, missing key file saves anyway (flag only), no-args update revalidates+persists+notifies, no `*.tmp` leftovers, invalid -> `SettingsFieldError` naming the field + nothing persisted + no listener notify, observer notified with a copy / multiple listeners / remove / decorator use, defaults when no config file, round-trip, package exports, subprocess test that the pure ui modules import no `gi` and `settings_dialog`/`app`/`views` stay lazy. `tests/test_ui_state.py`: path settings now accept empty (unset) with save/load round-trip; non-str still rejected. `tests/test_ui_widgets.py` (`importorskip("gi"`, skips in this sandbox, runs on the desktop): dialog constructs with the controller values, invalid IP -> error label visible + save blocked + nothing persisted, valid -> save persists + listener notified, missing key file flagged but save allowed, missing project_root blocks save, window has the `win.settings` action + shared controller and presents the dialog.
