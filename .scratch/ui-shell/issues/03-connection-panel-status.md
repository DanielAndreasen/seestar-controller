## Comments

Implemented keeping the strict pure/widget split (sandbox has no GTK — docs/wiki/assumptions.md; all link work is mock-only):

- **Pure layer** `ui/connection.py` (stdlib only, NO `gi` import — subprocess-enforced): `ConnectionStatus(str, Enum)` with `DISCONNECTED`/`CONNECTING`/`CONNECTED`/`RECONNECTING`/`ERROR` (a 5th state, `RECONNECTING`, because the device facade's resilience layer emits `connection_lost`/`reconnecting`/`reconnected` lifecycle events and the ticket's own integration test expects reconnecting→connected after `drop_connections()`). `ConnectionController(settings, *, device_factory=None, invoke_on_main=None)` — `settings` accepts a `SettingsController` (reads `.values`) or a plain `AppState` (reads `.settings`), re-read at every `connect()` call, so the scope IP + key path always come from the current settings. `connect(scope_ip=None, *, device_factory=None)` validates the IP (empty/invalid → `ERROR` synchronously, factory NOT called), transitions to `CONNECTING` synchronously, then runs the blocking `Device.connect` on a `threading.Thread`; success → `CONNECTED` storing the device + `device.state()`, failure → `ERROR` storing `"<ExcType>: <msg>"`. The pure layer stays GLib-free: results and listener notifications are marshalled through the `invoke_on_main` callable (default: direct call; the widget layer binds it to `GLib.idle_add`). Double connect while connecting/connected/reconnecting raises `ConnectionStateError(UIStateError, RuntimeError)`; from disconnected/error it retries. A generation counter invalidates in-flight results, so `disconnect()` during a pending connect discards the late result and disconnects the stale device. `disconnect()` is an idempotent no-op when already disconnected. Device lifecycle events (`connection_lost`/`reconnecting` → `RECONNECTING`, `reconnected` → `CONNECTED` + refreshed `device.state()`; event names re-declared as string constants so the pure package never imports `link` at module top) update the state and notify. Listeners (`add_listener`/`remove_listener`, idempotent, decorator-friendly — same pattern as `SettingsController`) receive a frozen `ConnectionSnapshot(status, scope_ip, scope_state, error)`. `default_device_factory` imports `link.device.Device` lazily inside the function. `describe_scope_state(scope_state)` formats the scope's current state duck-typed (`"mode idle, target ra 5.50 h, dec +12.25°"` / `"mode idle, no target"` / `"no scope state"`). `wait(timeout)` joins the worker (tests).
- **Widget layer** `ui/connection_panel.py` (`gi` at module top, re-exported lazily from `ui/__init__`): `ConnectionPanel(Gtk.Box)` packed `pack_start` into the header bar — a `Gtk.Button` with `Adw.ButtonContent` (Connect / Connecting… / Disconnect / Reconnecting… / Retry; `suggested-action` when connected, `error` css class on error, insensitive while connecting/reconnecting) plus a status `Gtk.Label` ("Disconnected" / "Connecting to <ip>…" / "Connected to <ip> — mode …, target …" — the scope's current state on a successful connect / "Link lost — reconnecting…" / "Connection error: <msg>" with `error` css). The panel is a controller listener and re-renders from each snapshot; button click connects from disconnected/error (catching `ConnectionStateError` for racing double-clicks) and disconnects otherwise. Errors surface through the listener notifications for now — ticket 04 wires the notification bus (banners) on top. `app.py`: `_invoke_on_main(callback) = GLib.idle_add(callback)`; `SeestarApplication` owns the shared `ConnectionController(self.settings_controller, invoke_on_main=_invoke_on_main)`; `SeestarWindow` packs a `ConnectionPanel` into the header bar and exposes `connection_controller`/`connection_panel`.
- **Exports:** pure names eager from `ui/__init__.py` (`ConnectionController`, `ConnectionStatus`, `ConnectionSnapshot`, `ConnectionStateError`, `ConnectionListener`, `DeviceFactory`, `InvokeOnMain`, `default_device_factory`, `describe_scope_state`, `CONNECTION_LOST_EVENT`, `RECONNECTING_EVENT`, `RECONNECTED_EVENT`, `LIFECYCLE_EVENTS`); `ConnectionPanel` lazy (PEP 562).
- **Tests:** `tests/test_ui_connection.py` (29 pure tests, headless, no gi, no real network): fake `device_factory` driving success → connected with scope state, failure → error with message, state-read failure → error (half-open device disconnected), empty/invalid IP → error without calling the factory, double connect rejected + retry after error, disconnect (from connected / idempotent no-op / clears error / while connecting discards the late result and disconnects the stale device), lifecycle events (reconnecting/reconnected, scope-state refresh on reconnect, stale-device events ignored), `invoke_on_main` marshalling (queued invoke: worker result not applied until the queue is drained — a `threading.Event` gate keeps the worker deterministically in-flight), listener add/remove/decorator notifications with frozen snapshots, `wait`, `describe_scope_state`, package exports, subprocess boundary test (pure ui imports no `gi`, no `link`, widget modules stay lazy). Integration with the REAL `Device` against `MockScope` on 127.0.0.1: connect → `CONNECTED` with `state().mode == "idle"`; `mock_scope.drop_connections()` → `RECONNECTING` → `CONNECTED` again via the resilience layer; a refused port → `ERROR` with `ConnectionRefusedError`. `tests/test_ui_widgets.py` (`importorskip("gi")`, skips in this sandbox, runs on the desktop): header panel reflects controller states (Connect/Disconnect button labels, `suggested-action` when connected, status line shows mode + target, error styling + message on failure, button clicks drive connect/disconnect), and the window's header panel shares the app's controller.
