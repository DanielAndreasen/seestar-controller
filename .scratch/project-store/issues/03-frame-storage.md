## Comments

Implemented in `src/seestar_controller/store/frames.py` (pure Python, stdlib only + lazy `astropy` import inside the functions that parse FITS/JD — same pattern as `link/mock_scope.py`, re-declared because the store must not import `link`; no GTK / no link imports, subprocess-enforced in tests), `FrameStoreError` added to `errors.py`, all exported from `store/__init__.py`. API: `store_frame(project, session_id, kind, fits_bytes, meta=None) -> Frame`, `list_frames(project, session_id=None, kind=None) -> list[Frame]` ordered by `jd` (ties by `id`), `get_frame_path(project, frame) -> Path`, `read_frame_bytes(project, frame) -> bytes`, `Frame` frozen dataclass `(id, session_id, kind, path, jd, utc, exposure, gain, target)` with `path` project-relative POSIX, kind constants `KIND_SUB`/`KIND_STACK`/`KINDS`/`FITS_SUFFIX` + `normalize_kind`. Documented choices: (1) order is file first, then db row — the FITS is written atomically (temp file in the SAME session dir + fsync + `os.replace`, temp removed on any failure incl. `KeyboardInterrupt`, same pattern as `Project.save_config` / `link/frames.py`), then the `frames` row is inserted in one transaction (`with project.db:`); if the insert fails the just-written file is removed (no orphan files); (2) JD from the FITS `DATE-OBS` header via `astropy.time.Time.jd` (isot/fits formats, then stdlib ISO), fallback to the written file's mtime (UTC) when `DATE-OBS` is missing/invalid — `utc` is the ISO-8601 `+00:00` ms-precision string of the same instant; (3) file name = `<jd:.6f>.fits` (~86 ms resolution) with a `-2`/`-3`… collision suffix (same policy as session ids); (4) `meta` (scope sidecar) overrides `exposure`/`gain`/`target`, FITS header cards `EXPTIME`/`GAIN`/`OBJECT` are the fallback; `target` stored as TEXT — string as-is, mapping as its `name` (else its JSON); (5) unknown session raises `SessionNotFoundError` BEFORE anything is written (clear error instead of the raw FK `IntegrityError`); frames may be added to a closed session; (6) bytes that are not a readable FITS file raise `FrameStoreError`; db-insert failures are wrapped in `FrameStoreError` (chained) after removing the file; `get_frame_path` rejects stored paths escaping the project dir. Tests: `tests/test_store_frames.py` (48 tests, tmp_path only, no network, astropy-generated FITS with DATE-OBS/EXPTIME/GAIN/OBJECT): sub + stack round-trip (file at the right path, byte-identical, db row with jd matching header DATE-OBS, utc ISO, meta values), header fallback + partial meta + target mapping/JSON + missing metadata → NULL, mtime fallback (no DATE-OBS and invalid DATE-OBS) checked against the file's `st_mtime`, jd-ordered listing across sessions with session/kind/combined filters + unknown-session filter → [], file-name format + collision suffix, interrupted write (monkeypatched `os.replace`) and `KeyboardInterrupt` at `fsync` leave NO partial file / no `*.tmp` / no db row, db-insert failure (RAISE(ABORT) trigger) removes the file and raises `FrameStoreError`, unknown session → `SessionNotFoundError` with nothing written, invalid kind → `ValueError`, non-FITS bytes → `FrameStoreError`, bad argument types → `TypeError`, path-escape guard, missing file on read, frames persist across reopen (full records + read-back + storing still works), public-API export test, module-boundary subprocess test.
