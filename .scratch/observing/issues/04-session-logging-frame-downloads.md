# 04: Session logging + frame downloads

**What to build:** data capture during the night — sub-frames and stacks downloaded into the current session as they arrive, plus a per-session event log (goto, stack start/stop, errors) viewable in the app. Demoable: mock scope produces frames during a run, they land in the project session and appear in the log.

**Blocked by:** 02, seestar-link 06, project-store 03

**Status:** implemented in a4fbe09

- [x] Frames arriving during stacking are downloaded into the session directory
- [x] Each stored frame has its metadata row in the project db
- [x] Session event log records goto/stack/error events with timestamps
- [x] Log viewable per session in the UI
- [x] Tests: mock run → frames + log present in temp project

## Comments

New pure module `src/seestar_controller/observing/capture.py` (executor layer: no gi, imports link.frames + store.frames/sessions + ui.notifications; lazy PEP 562 export from `observing/__init__.py` via `_EXECUTOR_EXPORTS`, so the package import stays link-free — subprocess + source-scan enforced in test_observing_queue.py / test_observing_capture.py):

- `SessionCapture(device, project, session_id, *, executor=None, poll_interval_s=0.5, invoke_on_main=None, bus=None, download_timeout=None, clock=time.time)` — the per-night capture. `start()` spawns a daemon worker that polls `device.download_frames(scratch, kind=, since=<per-kind watermark>)` for both kinds ("sub"/"stack") every `poll_interval_s` AND wakes immediately on every pushed `Stack` progress event (`add_stacking_progress_handler`); downloads run on the worker (network), the store runs on the db-owning thread via `invoke_on_main` (`GLib.idle_add` in the app; `poll_once()` runs a full cycle synchronously on the calling thread — used by tests and by `stop()`'s final cycle). Each frame is stored via `store.frames.store_frame(project, session_id, kind, fits, meta=meta_to_sidecar(meta, size=))` → file in `subs/<session>/` / `stacks/<session>/` + metadata row; dedupe by the Scope frame id (`_stored_ids`, seeded from the persisted log so a capture restart never double-stores). The `since` watermark is **per kind**: a Stack is recorded when stacking stops, i.e. after the last sub-frames, so a single watermark would skip subs recorded just before the Stack (found via a flaky e2e run, fixed + stress-tested). `stop()` is idempotent and never raises: joins the worker, disarms the progress handler, runs one final `poll_once()` on the calling thread, logs "capture stopped". Download/store failures become `error` log events + ERROR notifications on the bus (source `"capture"`) and never kill the night; a device without `download_frames` degrades to one WARNING + one error event. Properties: `device`/`project`/`session_id`/`executor`/`log`/`running`/`worker`/`poll_interval_s`/`since`/`stored_frame_ids`, `events()`, `add_listener`/`remove_listener`/`listeners`.
- Event log: the store has **no session-events API** (schema = sessions/frames/stars/measurements only) and store/ is read-only this ticket → the log lives in memory (`SessionLog`) and is persisted as JSONL at `subs/<session_id>/session_log.jsonl` (the session directory), whole-file atomic rewrite via `link.frames.atomic_write_bytes` (temp + fsync + `os.replace`); `SessionLog.load()` re-reads it on construction (skipping corrupt lines) and re-seeds the dedupe set. `SessionLog.append(kind, detail, *, source, state, frame_id, ts)` validates the kind, appends a frozen `LogEvent(ts, kind, detail, source, state, frame_id)` (with `to_dict`/`from_dict`), persists, and notifies listeners synchronously with per-listener isolation. Kinds: `goto`/`stack`/`error`/`frame`/`session`/`capture`/`executor` (`LOG_KINDS`); sources `executor`/`capture` (`LOG_SOURCES`). The executor's own `ExecutorEvent` log is mirrored into the session log on every apply (`classify_executor_event` maps detail prefixes: goto → goto, error/failed/lost → error, stack → stack, session → session, else executor; source=executor, state + ts preserved), so goto/stack start-stop/errors land in the log with timestamps; frame stores add `frame` events with `frame_id`. `session_log_path(project, session_id)` helper; `SESSION_LOG_FILE = "session_log.jsonl"`; `CAPTURE_SOURCE = "capture"`.
- Integration: `ObserveController` gained `capture_factory` (default `default_capture_factory(device, project, session_id, executor, **kwargs)` → `SessionCapture(..., executor=executor)`); `start_night` starts the capture right after `executor.start()` when a session was opened; the DONE/ABORTED snapshot branch stops it (`_stop_capture`, idempotent). Factory/start failures → WARNING notification "Session capture unavailable", the night runs regardless. `capture` property exposed.
- Widget: `observing/session_log_dialog.py` (gi at top, lazy `_WIDGET_EXPORTS`) — `SessionLogDialog(Adw.Dialog)` built from a `SessionCapture`: summary line (session id, event count, frames stored via `list_frames` — "N frame(s) stored (S sub, K stack)", best-effort) over one row per `LogEvent` (dim caption `YYYY-MM-DD HH:MM:SS · kind · source` + wrapped detail, `error` css class on error rows, `row.event` test hook), oldest first; Refresh button + automatic refresh on every new log event while open (listener removed on `closed`). `ObserveView` gained a "Session log" button (`log_button`/`log_dialog` properties): no capture yet → inline status "no session yet — start a night first"; otherwise `SessionLogDialog(capture).present(root)`. No `ui/` changes needed.
- Tests: `tests/test_observing_capture.py` (18 pure headless): `SessionLog` unit tests (append/persist JSONL/notify/frozen/ValueError, listener isolation, load roundtrip + corrupt lines), `classify_executor_event` table, `session_log_path`, constructor validation, **e2e against the real Device + MockScope** (2-target night, frames_per_target=2, manual `poll_once()` loop: subs + stacks land in the session — files exist via `get_frame_path`, metadata rows exposure=10.0/gain=50 — event log has goto/stack/frame/session entries with source=executor + ts>0, JSONL lines == events and round-trip equal, re-poll dedupe == 0), worker-loop test with a queueing `invoke_on_main` (arm/disarm of the progress handler, frame events, capture started/stopped, dedupe), Stack-progress wake test (poll_interval_s=60, one progress event → prompt poll), download failure → error event + bus ERROR (source "capture") + recovery, restart dedupe via the JSONL, device without `download_frames` → 1 WARNING + 1 error event, log listeners, `ObserveController` integration (capture starts on `start_night`, stops on DONE, frames + JSONL in the session; broken capture factory → WARNING + night still runs; `default_capture_factory` binds the executor), subprocess no-gi/lazy boundary, lazy exports. `tests/test_observing_widgets.py` extended (importorskip gi, skips in sandbox): log button in the layout, click without capture → status line, click with a capture → `SessionLogDialog` presented, dialog lists events + auto-refreshes on new events + Refresh button, error row css, summary counts stored frames.
